# kaalang Agent Guide

## Repository map

- `CONTRIBUTING.md` defines the workflow, code conventions, terminology policy,
  validation, and commit convention. Read it before making or committing
  changes.
- `docs/rfcs/` is the source of truth for kaalang syntax, semantics, scope, and
  design decisions. Read the relevant RFCs before conceptual or syntax changes.
- `docs/architecture.md` maps the compiler and renderer steps to their modules.
  Read it before changing how the crates divide the work.
- `GLOSSARY.md` names the terms the RFCs, crates, diagnostics, and tests share.
  Read it before naming a new concept.
- `crates/kaalang-compiler/` parses and resolves flows into the shared validated
  semantic model, decides the diagram, exposes its common arrangement checks,
  and lowers the verified plan to Rust. It also parses type declarations and
  expands datatypes.
- `crates/kaalang-macros/` holds only the procedural macro entry point: a
  `proc-macro` crate exports only macros, so anything else here could not be
  called, tested, or measured from another crate.
- `crates/kaalang-render/` checks cycle boundaries and compacts a verified
  arrangement into the shared rows, columns, and routes every renderer starts
  from.
- `crates/kaalang-svg/` measures the shared arrangement and renders standalone
  SVG without changing its structural layout, and lays out and renders type
  diagrams.
- `crates/kaalang-testing/` holds the shared test material: the fixture corpus,
  generated performance probes and cycle shapes, and the budget harness. Only
  tests depend on it.
- `crates/kaalang-cli/` is the `cargo kaalang` subcommand, shipped as the
  `cargo-kaalang` binary.
- `crates/kaalang/` exports the public macro and holds the test suite and the
  gallery in `examples/gallery/`. Its `.svg` files are generated by
  `just rust svg`; never edit one by hand.

## Documentation

Minimum text, maximum meaning. Every sentence states a fact, a decision, or a
rule the reader cannot get elsewhere; cut the rest. No introductions,
restatements, or summaries.

The README is an overview of the language: it links the RFC directory once and
never a specific RFC.
